# musik-alice

Клиент вашего сервера [musik](https://github.com/Haskey1/musik) для **Яндекс Станций**: музыка с сервера играет прямо
на колонке, а управлять ей можно голосом через штатную Алису («Алиса, включи Radiohead»), из консоли и из TUI.

Один небольшой Rust-бинарник `musikalice` (≈ 3 МБ) работает на самой колонке, без телефона и без отдельного
«проигрывателя»: он забирает треки по HTTP с вашего сервера musik, декодирует их и выводит в ALSA. Алиса при этом
остаётся на месте — пока вы с ней разговариваете, музыка тихо приглушается, а после диалога возвращается.

Проект сделан по образцу [Spotiya](https://github.com/klockky/spotiya) (то же самое, но для Spotify Connect): тот же
способ «подслушивать» Алису через локальный IPC, те же профили станций и тот же путь установки. Код написан заново под
API musik. Подробности — в [NOTICE](NOTICE).

> **Статус.** Код покрыт автотестами (90 штук: фейковый сервер musik, фейковая Алиса, настоящий декодер на реальных
> mp3/flac/aac, настоящий ALSA-вывод в устройство `null`), а ARM-бинарник собирается и проходит проверку ABI и запуск
> под qemu в GitHub Actions. **На живой колонке проект ещё не проверялся** — у автора кода не было доступа к станции.
> Подробнее — в разделе [Ограничения](#ограничения-и-что-не-проверено).

## Возможности

- **Воспроизведение с сервера musik** на колонке: персональное радио, исполнитель, альбом, трек, миксы («Микс дня»),
  избранное.
- **Голос через штатную Алису.** Программа слушает распознанные фразы Алисы и перехватывает только музыкальные команды
  про вашу библиотеку. Всё остальное («включи свет», «какая погода», «радио Маяк») остаётся Алисе.
- **Умный поиск по голосу.** Алиса распознаёт «Радиохед» кириллицей, а в библиотеке лежит `Radiohead`. Поиск сравнивает
  названия по фонетике (кириллица ↔ латиница, «куин» ↔ `Queen`), терпим к опечаткам распознавания и сам решает, что
  искали: исполнителя, альбом или трек (можно уточнить словами «песню», «альбом», «группу»).
- **Приглушение во время диалога.** Пока Алиса слушает, думает или говорит, музыка плавно опускается до 20 % за 80 мс
  и возвращается за 300 мс после диалога. Меняется только поток musik, системная громкость не трогается.
- **Охранник громкости.** Алиса во время диалога временами меняет общую громкость станции. Через 0,75 с после диалога
  выбранный вами уровень возвращается. Если вы сказали «громче/тише/громкость пять», новый уровень принимается как
  ваш выбор.
- **Обратная связь вкусу.** В musik уходят настоящие события: `track_start`, `progress`, `track_end`, `skip`, `like`,
  `dislike` — с `event_id` для безопасных повторов и `impression_id` для привязки к рекомендации. Радио учится так же,
  как при прослушивании в браузере.
- **Алиса называет трек.** После голосовой команды Алиса своим голосом говорит, что включилось: «Radiohead, Creep».
  Работает внутри колонки через штатную консоль прошивки, без Home Assistant и внешних сервисов
  (см. [Объявление трека](#объявление-трека)).
- **Звуковые сигналы.** Подтверждение консольных команд — короткий восходящий сигнал, «не вышло/нет связи» —
  нисходящий (для голосовых запросов без совпадения программа молчит, чтобы не перебивать Алису).
- **Консоль и TUI.** `musikalice play Radiohead`, `musikalice tui` — работает по `adb shell` или ssh.
- **Автозапуск и надзор.** Супервизор перезапускает службу при падении (2 с → 60 с с нарастанием); установщик
  откатывается на предыдущую версию, если новая не стартовала.
- **Mini 1, Mini 2 и «обычный» ALSA.** Профиль определяется по прошивке автоматически.

## Как это работает

```
 Голос ─► Алиса (штатная, на станции) ──► локальный IPC 127.0.0.1:9875
                                              │  события: «диалог идёт / закончился», «распознан текст»
                                              ▼
                      ┌──────────────── musikalice (служба) ─────────────────┐
                      │  alice.rs   разбор кадров IPC, переподключение       │
                      │  intent.rs  фраза → команда (или «это не нам»)       │
                      │  search.rs  фонетический поиск по каталогу           │
                      │  engine.rs  состояние сессии, события, громкость     │
                      │  player.rs  поток вывода + поток загрузки/декодера   │
                      │  control.rs unix-сокет: консоль и TUI                │
                      └──────┬───────────────────────────────────┬───────────┘
                             │ HTTP (Bearer-токен устройства)    │ PCM S16 стерео
                             ▼                                   ▼
                    сервер musik (Go)                       ALSA → динамик
         /api/library  /api/radio/start  /api/play
         /api/events   /api/stream/{id}?q=mp3 …
```

**Поток данных трека.** Движок просит у сервера сессию (`radio/start`, `play`, `mixes/…/play`), получает текущий
трек, плеер открывает `…/api/stream/{id}?q=mp3`, декодирует поток (symphonia, перемотка не нужна), приводит к стерео
и частоте устройства и пишет в ALSA. Когда трек доигран, движок отправляет `track_end`; сервер отвечает следующим
треком из очереди (`next`) или сообщает, что очередь закончилась.

**Как берётся управление у Алисы.** Перед запуском музыки голосовой командой программа отправляет Алисе по тому же
локальному IPC «отмени диалог» и «поставь штатный плеер на паузу» (чтобы она не начала свою музыку). Если фраза
не про вашу библиотеку или ничего не найдено, Алиса не трогается и отвечает сама.

**Потоки.** Служба — это несколько обычных потоков и каналы `mpsc`, без async-рантайма:

| Поток | Задача |
|-------|--------|
| `engine` | единственный владелец состояния сессии; принимает сообщения и принимает решения |
| `player` | владеет ALSA, мгновенно реагирует на паузу/скип/приглушение (опрос команд каждые ~50 мс) |
| `pipe` (на трек) | скачивает и декодирует; отдаёт PCM порциями по 100 мс через ограниченную очередь (~4 с) |
| `alice` | читает события Алисы, при обрыве переподключается и снимает приглушение |
| `control` | unix-сокет `/run/musikalice.control` (права 0600) |
| `job` / `event` | короткие потоки для запросов к серверу — движок никогда не ждёт сеть |

## Требования

- Яндекс Станция **Мини 2** или **Мини 1** (ARMv7, 32-битный userspace, glibc ≤ 2.23) с доступом по ADB.
  Любая другая Linux-колонка с ALSA — через профиль `generic` (без голоса; управление из консоли).
- Работающий сервер **musik**, доступный колонке по сети, и пароль (или пользователь + пароль) от него.
- Для установки «с компьютера»: `adb`, для сборки из исходников — Rust и (для ARM) `curl`, `qemu-user`, `xz-utils`.

## Установка

### Вариант 1. Прямо на колонке (одной командой)

Подключитесь к колонке (`adb shell`) и выполните — штатный `maind` скачает установщик и релиз с GitHub по HTTPS,
проверит SHA-256 и поставит программу:

```sh
(set -e; d=$(mktemp -d /tmp/musikalice.XXXXXX); trap 'rm -rf "$d"' EXIT; cd "$d"; echo 'Скачиваю musik-alice...'; get() { LD_LIBRARY_PATH=/system/vendor/quasar/libs /system/vendor/quasar/maind --gst-launch "souphttpsrc location=https://github.com/Haskey1/musik_alice/releases/latest/download/$1 ssl-strict=true ssl-ca-file=/etc/ssl/certs/ca-certificates.crt iradio-mode=false timeout=15 retries=1 ! filesink location=$1" >log 2>&1 && grep -Fq 'EOS: end of stream' log && ! grep -Fq 'ERROR from ' log && [ -s "$1" ]; }; get INSTALL_SHA256SUMS && get install.sh || { echo 'Не удалось скачать установщик.' >&2; exit 1; }; [ "$(wc -l <INSTALL_SHA256SUMS)" -eq 1 ] && grep -Eqx '[0-9a-f]{64}  install\.sh' INSTALL_SHA256SUMS && sha256sum -c INSTALL_SHA256SUMS || { echo 'Контрольная сумма установщика не совпала.' >&2; exit 1; }; sh install.sh)
```

Проверка без установки: добавьте `--check` к `sh install.sh`. Эта схема использует то, что в прошивке Мини 2 есть
`maind --gst-launch` с `souphttpsrc`; на других прошивках это не проверялось — тогда используйте вариант 2.

### Вариант 2. С компьютера по ADB (без интернета на колонке)

1. Скачайте со страницы [Releases](https://github.com/Haskey1/musik_alice/releases) файл
   `musikalice-armv7-linux-gnueabihf.tar.gz` (и `SHA256SUMS`, чтобы проверить его: `sha256sum -c SHA256SUMS`).
2. Загрузите и установите:

   ```sh
   adb push musikalice-armv7-linux-gnueabihf.tar.gz /tmp/
   adb shell 'cd /tmp && gzip -dc musikalice-armv7-linux-gnueabihf.tar.gz | tar -xf - && sh musikalice/scripts/install.sh'
   ```

Установщик (от root на колонке):

- временно включает запись в корневую ФС (если она read-only) и потом возвращает её обратно;
- кладёт файлы в `/data/opt/musik-alice`, init-скрипт `/etc/init.d/S99musik-alice` (автозапуск) и команду
  `/usr/bin/musikalice`;
- сохраняет предыдущий бинарник как `musikalice.prev` и откатывается на него, если новая версия не запустилась;
- **не трогает** `state/config.json` (адрес сервера и токен), поэтому обновление безопасно.

### Вариант 3. Из исходников

См. [Сборка, тесты и релизы](#сборка-тесты-и-релизы).

### Команда на компьютере

`bin/musikalice` — маленькая обёртка над `adb shell`, чтобы не заходить на колонку руками:

```sh
./bin/musikalice play Radiohead      # то же, что «musikalice play Radiohead» на колонке
./bin/musikalice tui                 # интерактивный экран
./bin/musikalice --device 192.168.1.50:5555 status
```

## Первый запуск

Получите токен устройства от сервера musik (пароль нигде не сохраняется):

```sh
musikalice login
```

Команда спросит адрес сервера (`192.168.3.141:8787`), имя пользователя (пусто — режим одного владельца) и пароль, проверит
`GET /api/health`, обменяет пароль на токен через `POST /api/auth/token`, проверит его `GET /api/auth/me` и сохранит
в `state/config.json` (права 0600). Можно без вопросов:

```sh
musikalice login --server 192.168.3.141:8787 --user anna --name "Кухня"
MUSIKALICE_PASSWORD=секрет musikalice login --server 192.168.3.141:8787
```

Служба стартует вместе с колонкой; запустить вручную — `musikalice start`. Проверка:

```sh
musikalice status
musikalice play Radiohead
```

Через несколько секунд после старта подтянется каталог (`library` в статусе покажет число треков). Он обновляется каждые 30 минут.

## Голосовые команды

Говорить можно с «Алиса» и без — программа получает уже распознанный текст.

| Что сказать | Что произойдёт |
|-------------|----------------|
| «включи Radiohead» / «включи Радиохед» | исполнитель: все треки в случайном порядке (`shuffle_artist`) |
| «включи альбом OK Computer» | альбом по порядку |
| «включи песню Creep» / «включи трек Creep» | трек: по умолчанию персональное радио от этого трека (`track_mode`) |
| «включи группу Queen», «исполнителя …», «певца …» | искать только исполнителей |
| «включи музыку», «что-нибудь послушать», «случайную песню», «моё радио» | персональное радио |
| «включи моё избранное», «любимые песни» | микс избранного |
| «включи микс дня», «мой микс …», «плейлист …» | микс/полка сервера по названию |
| «пауза», «стоп», «останови музыку» | пауза (только если сейчас играет musik) |
| «продолжи», «возобнови» | продолжить с паузы |
| «дальше», «следующий трек», «пропусти» | следующий трек (отправляется `skip`) |
| «назад», «предыдущий трек» | предыдущий трек (`session/back`) |
| «мне нравится», «лайк», «добавь в избранное» | событие `like` + добавление в избранное |
| «не нравится», «дизлайк» | событие `dislike` и переход к следующему |

Принципы разбора:

- Команды **«пауза/дальше/назад/лайк»** обрабатываются, только если musik уже играет или стоит на паузе. Иначе они
  относятся к штатному плееру Алисы, и мы не мешаем.
- Фразы про устройства и сервисы («включи свет», «включи телевизор», «радио Маяк», «включи сказку», «яндекс музыку»,
  «таймер») остаются Алисе. Чтобы проверить исполнителя с таким именем, скажите «включи **группу** Свет».
- «Громче/тише/громкость …» — штатные команды Алисы; программа не перехватывает их, а принимает новый уровень.
- Если по голосовому запросу ничего не нашлось, программа молчит и не вмешивается: Алиса обрабатывает фразу сама, как обычно
  (например, предложит свою музыку). Сигнал «не вышло» звучит только для команд из консоли и TUI.
- `voice_radio_fallback` (по умолчанию включён): голое «включи музыку» запускает ваше радио. Выключите, если хотите,
  чтобы такая фраза оставалась Алисе.

Голосовое управление можно отключить целиком: `musikalice voice off`.

### Объявление трека

Когда музыку включили голосом, Алиса называет первый трек: «Radiohead, Creep». Скобки вроде «(Remastered 2011)»
отбрасываются.

Как это устроено. В прошивке есть штатная консоль `maind --cli`. Её команда `q` (Text Input Query) отправляет Алисе
текстовый запрос так, будто его произнесли вслух. musik-alice на секунду запускает эту консоль и передаёт запрос
«повтори за мной Radiohead, Creep», и Алиса читает фразу своим голосом. Музыка на это время приглушается, как при
любом ответе Алисы. Свой же запрос программа узнаёт по префиксу «повтори за мной» и командой не считает.

Всё происходит на самой колонке: не нужны ни Home Assistant, ни токены, ни отдельный сервер синтеза речи. Нужен только
интернет, но без него Алиса не работает и так (распознавание и синтез у Яндекса в облаке).

| Режим (`announce`) | Когда Алиса называет трек |
|--------------------|---------------------------|
| `voice` (по умолчанию) | после голосовой команды, один раз — первый трек |
| `always` | каждый новый трек, включая следующие в радио |
| `off` | никогда |

Проверить голос без музыки: `musikalice speak Radiohead, Creep`. Тот же запрос вручную, без musik-alice:

```sh
(printf 'q\nповтори за мной Radiohead, Creep\n'; sleep 2; printf 'x\n') | \
  LD_LIBRARY_PATH=/system/vendor/quasar/libs /system/vendor/quasar/maind --cli >/dev/null 2>&1
```

## Консоль и TUI

На колонке команда `musikalice` (с компьютера — `bin/musikalice`):

| Команда | Действие |
|---------|----------|
| `login`, `config`, `profile` | настройка (см. ниже) |
| `start` / `stop` / `restart` | служба (через init-скрипт) |
| `play ЗАПРОС` | например `play Radiohead`, `play альбом OK Computer`, `play песню Creep` |
| `radio`, `mix НАЗВАНИЕ` | персональное радио, микс (`mix daily`, `mix микс дня`, `mix favorites`) |
| `pause`, `resume`, `toggle`, `next`, `previous` | управление воспроизведением |
| `like`, `dislike` | оценка текущего трека |
| `volume 0-100` | системная громкость (запоминается и защищается от Алисы) |
| `voice on\|off` | голосовое управление |
| `release` | остановить musik и освободить колонку для Алисы |
| `retry` | немедленно перезагрузить каталог |
| `status [--json]` | что играет |
| `tui` | интерактивный экран |
| `speak ТЕКСТ` | Алиса произносит текст (проверка объявлений; служба не нужна) |
| `run`, `supervise`, `quit` | служба в текущем терминале / с супервизором / остановить |

**Клавиши TUI:** `пробел` пауза · `n` дальше · `p` назад · `l` лайк · `d` дизлайк · `r` радио · `+`/`-` громкость ·
`v` голос вкл/выкл · `/` поиск (ввести запрос и Enter) · `q` выход.

## Настройки

`musikalice config` показывает настройки (токен скрыт), `musikalice config set КЛЮЧ ЗНАЧЕНИЕ` меняет. Работающая служба
подхватывает изменения сама (`duck_level` — после `restart`).

| Ключ | По умолчанию | Смысл |
|------|--------------|-------|
| `server` | — | адрес musik; `host:port` превратится в `http://host:port` |
| `token` | — | токен устройства (ставится командой `login`) |
| `device_name` | «Яндекс Станция» | имя устройства в musik (`device_id` в событиях, `client_id` = `musik-alice:<имя>`) |
| `quality` | `mp3` | `mp3` / `aac` / `mobile` — серверная перекодировка (`?q=`); `original` — файл как есть |
| `voice` | `on` | обрабатывать фразы Алисы |
| `voice_radio_fallback` | `on` | голое «включи музыку» запускает радио |
| `track_mode` | `radio` | «включи песню X»: `radio` — радио от трека, `single` — один трек |
| `shuffle_artist` | `on` | перемешивать треки исполнителя |
| `duck_level` | `0.2` | уровень музыки во время диалога (0.05–1.0; 1.0 — не приглушать) |
| `volume` | `auto` | сохранённая громкость 0–100 или `auto` (не вмешиваться) |
| `native_pause` | `on` | ставить на паузу штатный плеер Алисы при старте musik |
| `search_threshold` | `0.72` | строгость поиска 0.5–1.0: выше — меньше ложных совпадений |
| `earcons` | `on` | звуковые сигналы «принято / не вышло» |
| `announce` | `voice` | Алиса называет трек: `voice` — после голосовой команды, `always` — каждый трек, `off` — нет |

Почему по умолчанию `mp3`: оригиналы в библиотеке могут быть FLAC/ALAC, которые на слабом процессоре колонки тяжело
декодировать, а сервер умеет перекодировать налету. На быстрой сети и для lossless можно поставить `original` — декодер
понимает MP3, AAC, FLAC, Vorbis и WAV.

Файлы на колонке: `/data/opt/musik-alice/` (бинарник и скрипты), `state/config.json` (настройки и токен, 0600),
`state/profile.txt` (выбор профиля), журнал `/tmp/musik-alice.log` (в оперативной памяти, пропадает при перезагрузке).

## Профили станций

Профиль описывает, как говорить с конкретным железом: ALSA-устройство, формат, регулятор громкости и адрес IPC Алисы.

| Профиль | Устройство | Голос |
|---------|-----------|-------|
| `mini1` | Станция Мини (1-е поколение) | да, `127.0.0.1:9875` |
| `mini2` | Станция Мини 2 | да, `127.0.0.1:9875` |
| `generic` | любая Linux-колонка с ALSA | нет, управление из консоли |

```sh
musikalice profile              # что выбрано и что получилось
musikalice profile list         # список; «auto» определяет модель по прошивке
musikalice profile set mini2    # зафиксировать (потом: musikalice restart)
musikalice profile set auto
```

Свой профиль — JSON в `/data/opt/musik-alice/profiles/<id>.json` (формат — как у `profiles/generic.json`) или любой
файл: `musikalice profile set /путь/profile.json`. Поддерживается только формат `S16`; адрес голоса — только loopback.
Автоопределение: по `deviceType` в `/system/vendor/quasar/quasar.cfg`, затем по device-tree.

## Какие запросы к musik используются

Используется только публичное HTTP API сервера, ничего в нём менять не нужно. Авторизация — `Authorization: Bearer <токен>`.

| Запрос | Зачем |
|--------|-------|
| `GET /api/health` | проверка адреса при `login` |
| `POST /api/auth/token` | обмен пароля на токен устройства |
| `GET /api/auth/me` | проверка токена |
| `GET /api/library` | каталог для голосового поиска (раз в 30 мин) |
| `POST /api/radio/start` | персональное радио, в т. ч. от выбранного трека (`seed_track_id`) |
| `POST /api/play` | список треков (исполнитель, альбом, один трек) |
| `GET /api/mixes`, `POST /api/mixes/{kind}/play` | миксы и полки |
| `POST /api/events` | `track_start`, `progress` (раз в 30 с), `track_end`, `skip`, `like`, `dislike` |
| `POST /api/favorites` | добавление в избранное |
| `POST /api/session/back` | предыдущий трек |
| `GET /api/stream/{id}?q=mp3` | аудиопоток |

События отправляются с `event_id` (при сетевом сбое быстро повторяются с тем же идентификатором — сервер
дедуплицирует) и `impression_id` из ответа сервера.

## Сборка, тесты и релизы

Локально (x86-64 Linux, нужен `libasound2-dev` и `pkg-config`):

```sh
cargo test                 # 90 тестов
cargo clippy --all-targets -- -D warnings
cargo fmt --check
cargo run -- help
```

Без ALSA (например, на macOS): `cargo test --no-default-features`.

Бинарник для станции собирается кросс-компилятором Linaro 6.5 (glibc 2.23, как на Mini 1) и собственной
сборкой alsa-lib 1.1.8 без версионирования символов — иначе бинарник не запустится на старой прошивке:

```sh
scripts/bootstrap-arm.sh   # один раз: скачивает тулчейн и собирает alsa-lib (кэш в ~/.cache/musik-alice)
scripts/build-arm.sh       # сборка + проверка ABI (glibc ≤ 2.23, RPATH, отсутствие ALSA-функций со старым ABI)
scripts/smoke-arm.sh       # запуск под qemu-user
scripts/package.sh         # dist/musikalice-armv7-linux-gnueabihf.tar.gz + SHA256SUMS + install.sh
```

Всё это делает GitHub Actions ([`ci.yml`](.github/workflows/ci.yml)): `fmt`, `clippy -D warnings`, тесты, `shellcheck`,
затем ARM-сборка, проверка ABI, запуск под qemu и упаковка. По тегу `vX.Y.Z` (должен совпадать с версией в `Cargo.toml`)
артефакты публикуются как GitHub Release — оттуда ставит `install.sh`.

Выпуск версии:

```sh
# поднять version в Cargo.toml, закоммитить
git tag v0.1.0 && git push origin v0.1.0
```

## Диагностика

```sh
musikalice status            # состояние, сообщение об ошибке, размер каталога, громкость
cat /tmp/musik-alice.log     # журнал службы
musikalice run               # запустить на переднем плане (сначала musikalice stop)
```

| Симптом | Что проверить |
|---------|---------------|
| «служба не отвечает» | `musikalice start`; затем журнал `/tmp/musik-alice.log` |
| «токен недействителен» | `musikalice login` заново |
| «каталог ещё не загружен» | сервер недоступен с колонки: `status` покажет ошибку; `retry` после исправления |
| «Не нашла …» | в статусе `library` = 0? иначе попробуйте точнее или поднимите `search_threshold` ниже (0.65) |
| Фразы не ловятся | `musikalice profile` — должно быть «голос: Алиса на 127.0.0.1:9875»; `voice` — `on` |
| Музыка тихая/громкая после диалога | задайте `musikalice volume 40`: охранник вернёт этот уровень |
| Щелчки/обрывы звука | попробуйте `quality mobile` или проверьте сеть до сервера |
| Алиса не называет трек | `musikalice speak проверка`: если молчит — нет интернета у колонки; в журнале строки `[объявление]` |

## Ограничения и что не проверено

Честно о том, чего здесь нет и что нужно проверить на вашей колонке:

- **Не проверено на реальной станции.** Всё, что можно проверить без железа, проверено (см. тесты и CI). Но IPC-формат
  Алисы, ALSA-устройство Mini 1/2 и поведение прошивки взяты из Spotiya и не подтверждены на вашем устройстве. Если что-то
  не работает — пришлите `/tmp/musik-alice.log` и вывод `musikalice profile` / `musikalice status`.
- **Задуман клиент на самой колонке** (как Spotiya), а не навык Алисы на сервере. Серверный навык требует публичного
  HTTPS-адреса и не даёт приглушения, фоновой работы и обработки «пауза/дальше» без активации навыка.
- **Нет кнопок, светового кольца, дисплея Мини 2, спектра и AirPlay** — в отличие от Spotiya. Управление: голос, консоль, TUI.
- **Голосом Алиса только называет трек.** Ответы «не нашла» и подобные остаются звуковыми сигналами: чтобы не
  перебивать собственный ответ Алисы. Объявление идёт через облако Яндекса и звучит примерно через секунду после
  начала трека.
- **Между треками пауза около секунды** (новый HTTP-запрос и декодер на каждый трек); gapless не реализован.
- **Пауза отбрасывает недоигранный буфер ALSA** (≈ 250 мс), поэтому после «продолжи» последние десятые секунды
  трека могут быть пропущены. Позиция в TUI при этом приблизительная.
- **Нет перемотки внутри трека** и очереди «следующие треки» на экране — очередь целиком на стороне сервера.
- **Голосовой поиск работает по каталогу в памяти** и требует, чтобы колонка видела сервер при старте; офлайн-режима нет.
- **Транскодирование в MP3 по умолчанию** — компромисс между нагрузкой и качеством (см. `quality`).
- Распознавание фраз зависит от того, что Алиса прислала в IPC; в тихих/шумных условиях возможны ошибки. Ложные
  срабатывания ограничены списком «не наше» (свет, ТВ, радио-станции и т. п.) и порогом поиска.
